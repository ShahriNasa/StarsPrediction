# Security Policy

## Supported Versions

This repository is actively maintained for the latest public release only.

| Version | Supported |
|----------|-----------|
| Latest release | ✅ |
| Previous releases | ❌ |
| Development / experimental branches | ❌ |

---

## Reporting a Vulnerability

If you discover a security vulnerability related to this project, please report it responsibly rather than disclosing it publicly through GitHub issues.

Examples of security concerns include:

- Remote code execution vulnerabilities
- Dependency-related security issues
- Data leakage or unintended exposure
- Authentication or access-control issues
- Malicious model or dataset handling risks
- Unsafe execution within training or inference pipelines

### How to Report

Please submit a report through one of the following methods:

- Open a private security advisory through GitHub (preferred)
- Contact the maintainer directly via email

Please include:

- A description of the issue
- Steps to reproduce the vulnerability
- Potential impact
- Suggested mitigation (if available)

---

## Response Process

After a report is received:

1. Initial acknowledgement will typically be provided within **3–7 days**
2. The issue will be investigated and validated
3. If confirmed, a fix or mitigation strategy will be developed
4. Security updates will be released when appropriate
5. Public disclosure may occur after the issue has been addressed

---

## Scope

This policy applies to:

- Source code
- Training and inference pipelines
- Model checkpoints
- Data processing scripts
- Project dependencies

This policy does not cover:

- Third-party libraries or external services outside the project scope
- Vulnerabilities already publicly disclosed elsewhere
